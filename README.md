# Topic Police Bot

Небольшой Telegram-бот для одного чата с топиками и одного отслеживаемого пользователя.
Если другие люди за последние 10 минут общались только в одном топике и не писали
в General, бот пересылает туда новый пост отслеживаемого пользователя из General,
затем удаляет оригинал. Ответы на сообщения остаются на месте.

Правила: [продуктовая спецификация](docs/telegram-general-topic-bot-spec.md).
Уточнение для MVP: альбомы не пересылаются и не удаляются.

## Запуск

Нужны Python 3.14+ и `uv`.

```sh
uv sync
cp .env.example .env
```

Заполни `.env` рядом с `main.py`:

```dotenv
BOT_TOKEN=123456789:replace_with_your_bot_token
CHAT_ID=-1001234567890
WATCHED_USER_ID=123456789
WINDOW_MINUTES=10
```

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен бота, созданного через [@BotFather](https://t.me/BotFather) |
| `CHAT_ID` | Отрицательный числовой ID супергруппы с включёнными топиками |
| `WATCHED_USER_ID` | Положительный числовой ID пользователя; не username |
| `WINDOW_MINUTES` | Положительное число минут; по спецификации и по умолчанию `10` |

Добавь бота администратором в нужную супергруппу с правом **удаления сообщений**.
Он должен видеть новые сообщения и иметь возможность публиковать сообщения в топиках.
У ботов-администраторов есть доступ к сообщениям группы независимо от Privacy Mode
([Telegram FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)).
Защита контента («Запретить копирование») должна быть отключена.
При старте бот проверяет тип чата, защиту контента и право удаления.

```sh
uv run main.py
```

Либо после `uv sync`: `.venv/bin/python main.py`.
Переменные окружения процесса имеют приоритет над `.env`; файл читается относительно
проекта, даже если запускать `main.py` из другой директории. `.env` исключён из Git.
Остановка — `Ctrl+C`. Запускай только один экземпляр на токен.

### Ошибка `Chat not found`

Telegram не нашёл чат, доступный боту по указанному `CHAT_ID`. Проверь:

1. `CHAT_ID` — полный ID супергруппы в Bot API, например `-1001234567890`.
   Если ссылка на сообщение имеет вид `https://t.me/c/1234567890/42`,
   ID супергруппы вычисляется как `-(1000000000000 + 1234567890)` → `-1001234567890`.
   Число `42` — ID сообщения; у ссылок на топики могут быть дополнительные части.
   Простого минуса перед `1234567890` недостаточно. Формула применима к числу
   сразу после `/c/`, а не к ID обычной группы или произвольному числу из URL.
   Для супергруппы в Telegram Web K с адресом `https://web.telegram.org/k/#-1234567890`
   используй ту же формулу с числом `1234567890`.
   Надёжный источник готового значения — `message.chat.id` в ответе Bot API.
   [Формат ID в документации Telegram](https://core.telegram.org/api/bots/ids#supergroupchannel-ids).
2. В группу добавлен именно тот бот, чей токен записан в `BOT_TOKEN`.
   Для работы этого проекта назначь его администратором с правом удаления сообщений.
3. Переменная `CHAT_ID` в окружении терминала или IDE не перекрывает значение из `.env`.

При включённой опции **Raised Exceptions** VS Code остановится на исключении
ещё до того, как `main()` выведет подсказку. Нажми **Continue**, чтобы увидеть её
в терминале. Отключение этой опции убирает остановку отладчика, но ошибку настройки
нужно исправить отдельно.

## Отладка в VS Code

1. Открой корневую папку `topic-police-bot` в VS Code.
2. Установи рекомендованные расширения Microsoft **Python** и **Python Debugger**.
3. Выполни `uv sync` в терминале проекта и заполни `.env`, как описано выше.
4. Поставь breakpoint, например на строке `settings = Settings()` в `main.py`.
5. В **Run and Debug** выбери **Topic Police Bot** и нажми **F5**
   (на Mac при необходимости **Fn+F5**).

Конфигурация `.vscode/launch.json` запускает `main.py` через Python из `.venv`.
Логи выводятся во встроенный терминал. Настройки бота читаются из `.env`;
токен в `launch.json` добавлять не нужно.
Если редактор выбрал другой Python, выполни **Python: Select Interpreter**
через палитру команд и выбери окружение `.venv`.

Перед запуском останови другие экземпляры бота с тем же токеном.
Отладка выполняет обычные пересылки и удаления в чате из `.env`.
Пауза, из-за которой интервал между получениями updates превысил 45 секунд,
начинает прогрев заново: переносы возобновятся после полного `WINDOW_MINUTES`.
Для остановки на исключениях, которые перехватывает `main()`, включи
**Raised Exceptions** в секции **Breakpoints**.

Описание параметров: [отладка Python в VS Code](https://code.visualstudio.com/docs/python/debugging).

## Поведение

- Long polling через `python-telegram-bot`; webhook при старте удаляется.
  Накопленные до запуска updates отбрасываются.
- После первого успешного получения updates бот наблюдает полное окно, прежде чем
  начать переносы. Любая ошибка polling, пауза получения updates более 45 секунд
  или изменение членства/прав бота запускает новый прогрев. Отсчёт после ошибки
  начинается с восстановления получения updates.
- Если у бота забрать права администратора или удаления, переносы прекращаются.
  После восстановления прав бот снова собирает полное окно активности.
- Учитываются новые сообщения людей, включая медиа и ответы. Активность датируется
  временем отправки сообщения; окно проверяется при получении update. Боты,
  редактирования, служебные события и сам отслеживаемый пользователь не создают активность.
- Авторство от имени канала/анонимного администратора считается неопределённым.
  Такие сообщения в General блокируют переносы. В другом топике они не могут
  сами создать подходящий целевой топик и учитываются как возможная неоднозначность.
- Решение принимается при получении сообщения. Оставленные сообщения позднее
  не пересматриваются. Будущая активность не меняет выбранный для поста топик.
- Пересылка и удаление выполняются последовательно. При ошибке или неизвестном
  результате пересылки оригиналы сохраняются; повторных попыток переноса нет.
  Ошибка удаления также не вызывает новую пересылку. Для неподходящих сообщений
  бот ничего не пишет в чат.
- Состояние хранится только в памяти: времена активности и ID обрабатываемых сообщений.
  Текст сообщений и токен в журнал не выводятся.
  Журнал идёт в терминал: этап операции, класс ошибки, ID сообщений/топика.

## Ограничения MVP

Альбомы отслеживаемого пользователя остаются на месте. Альбомы других участников
учитываются как активность в соответствующем топике или General.
Одиночные фотографии, файлы, голосовые сообщения и стикеры обрабатываются по тому же
правилу, что и текст, если Telegram разрешает пересылку.

При аварийной остановке между пересылкой и удалением возможен дубль:
постоянное хранилище состояния не используется.

Базовые проверки настроек и правил переноса не обращаются к Telegram:

## Docker и CI/CD

Push в `main` запускает `.github/workflows/deploy.yml` на сервере runner
`ftagn-nl-l`. Один job использует GitHub Environment `prod`, собирает образ
из `Dockerfile` и обновляет контейнер через Docker Compose на том же сервере.
Тесты выполняются внутри сборки; финальный слой зависит от их успешного завершения.
В образ попадают Python 3.14, зависимости из `uv.lock` и код бота, без тестов и `.env`.
Образ `topic-police-bot:local` остаётся на сервере, публикации в registry нет.
Для сборки нужен доступ к базовым образам Python/uv и пакетам PyPI.

Один раз перед первым деплоем:

1. Разреши runner доступ к этому репозиторию и назначь ему уникальную метку
   `ftagn-nl-l` вместе с `self-hosted` и `linux`. Имя runner само по себе
   не является меткой для `runs-on`
   ([маршрутизация по меткам](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/use-in-a-workflow)).
   Нужен Actions Runner версии 2.327.1 или новее для
   [`actions/checkout@v6`](https://github.com/actions/checkout/tree/v6).
2. Установи Docker Engine и Docker Compose 2.20+ (`docker compose`).
   У пользователя runner должен работать `docker info` без `sudo`, а Docker
   должен запускаться при загрузке сервера. Python и `uv` на хосте не нужны.
3. В **Settings → Environments → prod** задай secret `BOT_TOKEN` и variables
   `CHAT_ID`, `WATCHED_USER_ID`, `WINDOW_MINUTES` (например, `10`).
   Все четыре значения обязательны для Compose. Если у environment включено
   ручное approval, job будет ждать его; для автоматического деплоя разреши `main`
   без такого ожидания.
4. Перед первым запуском останови прежний экземпляр бота с тем же токеном,
   если он запускался вручную или другим сервисом.

Деплои выполняются последовательно; новый push не прерывает текущий job.
Ошибка тестов, сборки или проверки настроек оставляет текущий контейнер работающим.
Compose использует постоянное имя проекта `topic-police-bot`, поэтому повторные
деплои заменяют его контейнер. После замены начинается полный прогрев
`WINDOW_MINUTES`; портов и постоянных томов нет. `restart: unless-stopped`
перезапускает бот после сбоя или перезапуска Docker. Логи ограничены 3 файлами
по 10 МБ. Для корректной остановки Compose отправляет `SIGINT`, который обрабатывает
`asyncio.run` в существующем коде.

Для ручного запуска из корня проекта заполни `.env` по примеру выше:

```sh
docker compose config --quiet
docker compose build --pull
docker compose run --rm --no-deps bot python -c 'from topic_police_bot.config import Settings; Settings()'
docker compose up --detach --no-build --wait --wait-timeout 60
docker compose ps
docker compose logs --tail=100 bot
```

В Actions значения передаются через окружение процесса; `.env` там не создаётся,
секреты не передаются в build args. Не выводи `docker compose config` без `--quiet`:
полная конфигурация содержит токен. Для ручных команд Compose тоже нужны эти
переменные или локальный `.env`; GitHub Environment доступен только во время job.

`--wait` подтверждает состояние running контейнера, но не готовность Telegram:
HTTP healthcheck у бота нет. После первого деплоя проверь в логах
`Long polling started` и `Observation started`, отсутствие повторных рестартов
и работу бота после прогрева. При ошибке токена/прав исправь `prod` и повторно
запусти последний workflow через **Actions → Deploy → Re-run jobs**.
Для отката кода сделай `git revert` ошибочного коммита и push в `main`;
это снова запустит тесты, сборку и деплой. Автоматического отката нет.
Ручная остановка: `docker compose stop bot`.

## Код

- `main.py` — запуск и безопасные сообщения об ошибках.
- `topic_police_bot/config.py` — настройки и валидация через Pydantic Settings.
- `topic_police_bot/moderation.py` — окно активности, правила и перенос.
- `topic_police_bot/runtime.py` — проверка прав и цикл long polling с восстановлением.
